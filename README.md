## 一、与小程序的关系

| | 微信小程序版 | 网页版（本目录） |
| --- | --- | --- |
| 位置 | `../family-food-manager/` | 本目录 |
| 运行环境 | 微信客户端 | 任意现代浏览器 |
| 数据存储 | 云开发数据库 / 本地 Storage | 浏览器 `localStorage` |
| 业务逻辑 | `miniprogram/utils/biz.js` | `js/biz.js`（**自动生成，同源**） |
| 数据访问 | `miniprogram/utils/db.js`（双驱动） | `js/db.js`（**自动生成，走 localDriver**） |
| 视图层 | WXML + WXSS + Page | HTML + CSS + 原生 JS |
| 登录 | `wx.login` + 云函数 | 无（本机匿名用户） |

> ⚠️ **网页版不是小程序，也没法变成小程序。** 小程序必须在微信开发者工具里用真实 AppID 上传、提交审核、发布。本目录只是同一套业务逻辑的 Web 呈现，用于快速分享和演示。

### 怎么做到「业务逻辑零改动」

`miniprogram/utils/db.js` 本来就设计了**双驱动**：检测不到 `wx.cloud` 就自动降级到 `localDriver`（基于 `wx.getStorageSync` / `wx.setStorageSync`）。

网页端只需要补一个 `js/wx-shim.js`，把这两个 API 映射到 `localStorage`，并**刻意不提供 `wx.cloud`**——于是：

```
biz.js  ← 一字未改
db.js   ← 一字未改（自动选中 localDriver）
format.js / constants.js / seed-data.js ← 一字未改
```

`tools/build-web.js` 只做三件事：`module.exports = X` → `window.FFM.<name> = X`、`require(...)` → `window.FFM.<name>`、外层包 IIFE（隔离顶层 `const`，避免多脚本重复声明）。

**收益**：改一处业务规则，小程序和网页同时生效，不存在两份实现漂移。

## 三、功能

7 个页面（底部 tabbar 5 项 + 2 个二级页）：

| 页面 | 路由 | 能力 |
| --- | --- | --- |
| 首页 | `#/index` | 本周预算进度、每日成本横滑卡、今日菜单、纸坊物价总览、价格涨跌榜、快捷录入物价 |
| 食材库 | `#/category` | 四分类切换、搜索、排序、新增/编辑/删除食材、图片上传 |
| 食材详情 | `#/ingredient?id=` | 当前售价、更新售价（留历史）、加入食谱、价格波动图、价格记录明细 |
| 食谱规划 | `#/recipe` | 周导航、整周/单日视图、加菜、改用量、删条目、复制上周、清空某天 |
| 采购清单 | `#/shopping` | 汇总卡、分类分组、勾选、手动加项、导出清单文本、完成采购记账 |
| 成本统计 | `#/stats` | 预算对比、每日支出/计划柱状图、分类占比与金额、近 6 周趋势、消费明细、我的 |
| 消费记录 | `#/records` | 采购记录 / 历史食谱成本双段切换、展开明细、删除 |

**核心机制：成本实时联动**
食谱条目只存「食材 ID + 用量 + 单价快照」，渲染时按**当前市价**重算。改一次菜价 → 食谱成本 → 单日 → 整周 → 预算对比，全链路自动更新。

**首次使用**：打开即自动灌入 62 种纸坊菜市场参考价 + 近 4 周历史价格（幂等）。
想快速看完整效果：**统计 → 我的 → 数据管理 → 载入示例数据**（用户主动触发，不会偷偷造数据）。

## 四、本地运行

因为用了 `localStorage` 和相对路径资源，建议起一个本地服务器（`file://` 下部分浏览器会限制存储）：

```bash
cd family-food-manager-web
python -m http.server 8899
# 打开 http://127.0.0.1:8899
```

或者直接双击 `index.html`——Chrome / Edge 下也能跑。

## 五、重新生成 / 同步逻辑

修改了小程序端的 `utils/biz.js` 或 `config/*.js` 之后：

```bash
cd ../family-food-manager
node tools/build-web.js     # 重新生成网页版的 5 个数据层文件
node tools/web-smoke.js     # 离线跑一遍端到端业务流（71 项断言）
```

`web-smoke.js` 用 Node 的 `vm` 造一个浏览器沙箱（内存 localStorage、无 `wx.cloud`），加载生成后的文件并跑完整业务流：初始化 → 分类查询 → 改价留史 → 排食谱 → 成本重算 → 统计聚合 → 清单聚合 → 记账落库 → 预算设置 → 食材增删改。

## 六、设计系统

| 语义 | 色值 | 用途 |
| --- | --- | --- |
| 品牌绿 | `#2e9e6b` | 主操作、选中态、进度条 |
| 价格 | `#e8613c` | 所有金额数字 |
| 涨 | `#e5534b` | 价格上行（**国内习惯：涨红**） |
| 跌 | `#2e9e6b` | 价格下行（**跌绿**） |

- **核心数字**统一 `DIN Alternate` 字体（等宽、辨识度高），金额一律 `round2` 到分。
- **零 Emoji**：全部用程序化生成的线性图标 PNG；`ui.js` 的 `icon()` 带 `dark → gray → brand → muted → white` 五级回退链，任何情况下不出破图。
- **手机外壳**：桌面端居中显示 414px 宽的圆角卡片，移动端全屏。

## 七、已知限制

| 限制 | 说明 |
| --- | --- |
| 数据仅存本机 | 换设备/换浏览器不同步；清浏览器数据会丢失 |
| 无登录 | 没有账号体系，`localStorage` 就是全部 |
| 图片以 DataURL 存储 | 选图直接读成 base64 存 `localStorage`，大图可能撞配额（约 5MB） |
| 无后端 | 食谱无法分享给家人、无法多端协作 |

需要跨设备同步时，用小程序版接微信云开发，或给网页版加一个后端（`db.js` 换一个 driver 即可，业务层不用动）。
